# 需求文档：RPC 框架

## 概述
构建一个高性能、模块化的 C++ RPC 通信框架，支持服务注册发现、负载均衡、多种序列化协议、数据压缩加密，实现客户端与服务端之间的透明远程调用。

## 背景
分布式系统中，服务间通信是核心基础设施。需要一个统一的 RPC 框架来：
- 解耦服务发现与调用逻辑
- 提供可插拔的序列化/压缩/加密能力
- 保证高并发下的性能和可用性

### 各模块职责

| 模块 | 目录 | 职责 |
|------|------|------|
| **Registry** | `registry/` | 基于 ZooKeeper 的服务注册与发现；服务端启动时注册临时节点（IP:Port）；ZK 通过 Watch 机制探活，节点失效自动清理 |
| **Load Balancer** | `conn_balancer/` | 从 ZK 获取可用服务列表后，按策略（轮询/随机/加权）选择目标服务器 |
| **Connection** | `network/` | 基于 Boost.Asio 的 TCP 长连接管理；连接池、心跳保活、断线重连 |
| **Serializer** | `serializer/` | 支持多种序列化协议（Protobuf / JSON / 自定义二进制），可插拔扩展 |
| **Compress** | `compress_data/` | 数据压缩模块（zstd），减少网络传输量 |
| **Encrypt** | `encrypt/` | 混合加密：非对称加密交换对称密钥，对称加密保护数据载荷 |
| **Thread Pool** | `thread_pool/` | 服务端并发执行 RPC 任务，避免阻塞 IO 线程 |
| **Protocol** | `protocol/` | RPC 协议定义（RpcHeader / RpcRequest / RpcResponse），统一报文格式 |
| **Service** | `service/` | 服务接口基类与 ServiceManager 单例，管理注册的服务实例 |

### 数据处理管线（Pipeline）

```
发送端:  struct → serialize → compress → encrypt → wire (TCP)
接收端:  wire (TCP) → decrypt → decompress → deserialize → struct
```

处理顺序不可变，每层独立封装，层次间通过 `std::string` (二进制缓冲区) 传递。

### 场景
<!-- 用户/调用方如何使用这个功能？描述 1-3 个典型使用场景 -->
1.微服务架构中的服务间调用
将一个大型单体应用拆分为多个独立部署的服务（订单服务、用户服务、库存服务等）。这些服务通常由不同团队维护、使用不同编程语言或运行在不同节点上。前端或网关需要调用多个服务完成一个业务请求。

透明调用：就像调用本地函数一样调用远程服务，隐藏网络细节。

高性能：相比 HTTP + JSON，RPC（如 gRPC、Thrift、自定义二进制协议）序列化更小、传输效率更高。

服务发现：配合 ZooKeeper 实现动态注册与订阅（您的 service_registry.* 和 ZooKeeper 模块正好解决这个问题）。

典型示例：
电商下单流程：
OrderService 调用 UserService.GetUserInfo() 和 StockService.DeductStock()，通过 RPC 完成分布式事务协调。

2. 分布式计算与任务调度
场景描述
海量数据处理、机器学习训练、视频转码等需要将任务拆分到多台工作节点并行执行。主节点负责任务分割与调度，工作节点计算后返回结果。

RPC 价值

任务分发：主节点通过 RPC 将任务参数、代码依赖或数据分片发送给工作节点。

状态汇报：工作节点定期用 RPC 上报心跳、进度、中间结果。

弹性伸缩：结合 ZooKeeper 临时节点实现工作节点的自动上线/下线感知，动态调整任务分配。

典型示例
MapReduce 框架中的 Master 通过 RPC 向 Worker 下发 map/reduce 任务，Worker 完成后回调 Master。

3. 服务治理与网关路由
场景描述
企业内部有数十甚至上百个 RPC 服务，需要统一的流量控制（限流、熔断、降级）、鉴权、日志监控、灰度发布（金丝雀发布）能力。通常会引入 API 网关或 Sidecar 代理。

RPC 价值

拦截器链：在 RPC 客户端/服务端框架层嵌入统一 filter，实现无侵入的治理能力。

动态路由：利用 ZooKeeper 存储配置（如权重、黑白名单），RPC 框架实时拉取或监听变更，将请求路由到特定版本或区域的服务实例。

负载均衡：集成 conn_balancer/ 模块，实现轮询、一致性哈希、最少连接数等策略。

典型示例
一个订单服务同时部署了 v1（稳定版）和 v2（灰度版），RPC 框架根据请求头中的 x-user-id 决定是否路由到 v2，其余请求走 v1。

- 压缩：zstd
- 日志：spdlog

- 平台：Windows (MinGW)
